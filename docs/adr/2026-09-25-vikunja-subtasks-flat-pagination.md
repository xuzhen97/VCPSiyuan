# 子任务保留平铺分页，在 Dock 按已加载任务组树

- Status: Accepted
- Date: 2026-09-25

## Context

Vikunja v2.5.0 以任务关系（`subtask` / `parenttask`）而非 `parent_task_id` 表示父子任务，且同一任务可有多个父任务。VCPSiyuan 的收件箱和全部任务视图已经按服务端筛选结果进行平铺分页；页签数、页脚总数和“加载更多”均依赖该口径。Vikunja 的 `expand=subtasks` 则按根任务分页，还可能带出未命中筛选的子任务，不能直接替换现有查询。

## Decision

Dock 继续使用原有平铺筛选及分页查询，不使用 `expand=subtasks` 改写列表语义。任务映射只解析 `related_tasks` 中的直接父子关系；仅在当前已加载且命中筛选的任务之间构造多级可展开树，不额外注入未命中任务。若父任务不可见，子任务作为根行；若有多个可见父任务，以当前已加载列表中最先出现的父任务作为唯一展示位置（同序时按 ID 决定），不修改服务端关系。页签总数、页脚已加载任务数及加载更多均保持平铺任务口径，折叠不改变计数。详情页如实显示直接父子关系；新增及解除关系使用 Vikunja 任务关系接口，解除不删除任务。

## Consequences

- 原有筛选、分页与计数语义稳定；多父子任务在同一列表中只出现一次，筛选掉父任务也不会藏起匹配的子任务。
- 跨页加载到父任务后，子任务会重新归位；加载顺序、刷新和筛选变化均须验证去重、确定性、展开状态和可达性。
- 未加载的后代不会因展开而提前出现；离线快照只能显示已缓存关系，不能写关系。
- 新建任务与建立关系是非原子操作；创建成功而关联失败时必须保留已创建任务 ID，只重试关联，避免重复创建。

## Alternatives considered

- **直接使用 `expand=subtasks`**：拒绝；按根任务分页并可能附带未命中筛选的后代，改变页签数量、加载更多和筛选规则。
- **前端一次取齐全部任务再组树**：拒绝；破坏分页的资源边界，难以适应大任务库。
- **始终平铺并重复显示在父任务下**：拒绝；同一任务重复出现且数量含义混乱。
